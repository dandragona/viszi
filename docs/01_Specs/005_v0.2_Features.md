# 005 — v0.2 Features

The features added to viszi after the initial v0.1 walking skeleton. Implementation details live in `docs/02_Architecture/`.

## Call graph

The analyzer now extracts function-call edges in addition to import edges. For every JS/TS file:
- Parses the names brought into scope by each `import` / `require`.
- Scans the file for `name(` patterns and records a callsite whenever `name` is one of those imported bindings.
- Emits `kind: 'calls'` edges in the dependency graph (alongside the existing `kind: 'imports'` edges).
- The module-level prompt now includes a `callsModules` field for each module, so Claude can choose `kind: 'calls'` vs `'imports'` when emitting diagram edges.

The frontend renders call edges with a dashed violet stroke and a subtle "calls" label so they read distinctly from import edges.

Python and Go parsers currently emit empty `callsites` arrays — they ship in v0.1 form pending tree-sitter integration.

## Static HTML export

`viszi export [path] [--out viszi.html]` produces a **single self-contained HTML file** containing the React bundle, the dark theme CSS, and every diagram inlined as JSON inside `window.__VISZI_DATA__`.

- The frontend's `api.ts` checks for `window.__VISZI_DATA__` first and falls back to `/api/*` only when it isn't present (`STATIC_MODE` flag).
- Live progress (`ProgressBanner`) is suppressed in static mode.
- Output file is fully shareable: it works offline, opens in any browser (modulo `file://` CORS for some browsers — serving over `http://` is recommended).

## Search palette (Cmd-K / Ctrl-K)

A global keyboard shortcut opens a fuzzy search modal indexing **every diagram, every component, and every flow step**.

- Index is emitted at write time as `<output>/search.json` and served via `/api/search`. In static mode it ships inside the inlined data blob.
- Match algorithm is a small homemade ranker (no Fuse.js dep): substring + position bonus + token-boundary bonus + label-bias.
- Keyboard nav: ↑ / ↓ to move, ↵ to open, Esc to close.
- Selecting an entry navigates to `/d/<diagramId>?focus=<anchor>` so the URL captures both the diagram and the in-diagram anchor (a future "focus this node" UX hook).

## Live progress over WebSocket

When `viszi <path>` runs with `--serve` (the default), the server **boots before the analysis starts**. The browser opens immediately and shows a live progress banner streamed over a WebSocket.

- A new `EventBus` (`src/server/eventBus.ts`) is the bridge between the orchestrator and the WebSocket subscribers.
- The orchestrator's `onProgress` and `onDiagramAdded` callbacks publish `{ type: 'progress' | 'diagram-added' | 'done' | 'error' }` messages.
- The WebSocket endpoint `/ws/progress` replays the current state to every new connection, so refreshes don't lose context.
- The frontend's `ProgressBanner` reconnects after disconnects with a 2-second backoff.
- When the bus signals `done`, the App refetches `/api/index` and renders the diagrams.

## Backwards-compat notes

- `SCHEMA_VERSION` bumped from `1` → `2` because the components prompt now mentions call edges. Existing caches are invalidated.
- The `ParsedFile` type gained `callsites: CallsiteRef[]` — every parser now sets this (Python and Go set it to `[]`).
- The `DepEdgeAttrs` shape gained `importCount` + `callCount` fields; `weight` is now their sum and is kept for backwards compatibility.
